# 章・条・項・号の検出手順の見直し（仕様書）

2026-11-05 の点検（PR #18）の続き。新しいセッションで、下の「進め方」の順に、段階ごとに別のPRで進める。

## 目的

今の検出手順は、1行ずつ前の行だけを見てその場で決め、言葉の例外規則（助詞・単位・注記の語）で補っている。
そのため、規則を足すたびに別の書き方を壊しやすい（PR #18 の再レビューで、修正による新しい誤判定が7件出た）。
手順の組み方を直し、番号の並びや前後の単位といった構造の手がかりで判定するようにして、ほかの就業規則でも同じ誤判定が起きないようにする（AGENTS.md の方針）。

## 背景：手順が原因の誤検出と、回りくどい箇所

場所は `py/kisoku_parser.py`（PR #18 のマージ後の main）。

| # | 手順の問題 | 起きる誤検出 | 状態 |
|---|---|---|---|
| ① | 停止語（附則など）と本文の始まりを、目次かどうかを見る前に、段落1つだけで決めている（`parse_kisoku` の段落ループ） | 手打ちの目次に「附則 ……30」があると、そこで解析が止まり本文全体が整形されない／目次に「第１条（目的）……1」が並ぶと条が二重に入る／章の目次が空の章として入る／章の無い規則で第1条の前の「（目的）」が前付けに入る | 未修正 |
| ② | 行を結合してから、結合した文字列を正規表現で切り直している（`merge_lines` → `classify_line`） | 「第1条」＋「１　この規則は」が条と判定できず消えた | PR #18 で応急処置（見出しだけの行は空白を挟んで結合） |
| ③ | 括弧だけの行を、次の行を見ずに条タイトルと決めている（`classify_line` の `RE_TITLE`） | 保留と戻しの仕組み（`build_tree` の `_flush_pending`）が必要になり、戻し漏れで消えた | PR #18 で戻し先を補った |
| ④ | 号の階層を、木を作る前に文書全体で1つの表として決めている（`marker_hierarchy.MarkerAnalyzer.learn`） | 条・項ごとに記号の使い方が違うと崩れる（（１）の下の①が（１）と同列になる）。記号の無い行で入れ子の状態をリセットし、後の条で深さを上書きする | 未修正 |
| ⑤ | 図の周りの判定（`fig_adjacent`）を構造の判定より前にしている | 図の直後3段落以内にある次の条の括弧タイトルが図に取り込まれ、条タイトルが空になる | 未修正 |
| ⑥ | 読み取った条・項・号の番号を、確かめに使っていない（出力は自動採番） | 偽の章・条ができても気づけず、以降の番号が黙ってずれる | 誤検出の多くの背景 |

回りくどい箇所:
- 章・条の判定（`match_chapter`・`match_article`）を9か所で、号の記号の判定（`identify_symbol`）を10か所で呼び、結果を引き継いでいない（PR #18 時点。`is_layout_paragraph`、`_heading_state`、`_starts_new_unit`、`classify_line`、`classify_auto`、`parse_kisoku` 内の図の判定・本文の始まりの判定・記号の学習、`MarkerAnalyzer` など）。
- `build_tree` に、上流で文脈を見ずに決めた結果の後始末が積み上がっている（号の細分の格上げ `_promoted`、「2.」を号に直す `last_dot`、「１０」を本文に戻す処理、括弧行の保留と戻し、入れ先の無い本文の救済 `_orphan`）。
- 号の階層の学習が無い場合の旧処理（`maru_is_sub`・`detect_item_hierarchy`・`classify_line` 内の `RE_ITEM_MARU`／`RE_ITEM_PAREN` の分岐）は、ブラウザ版でも `marker_hierarchy.py` を必ず読み込むので通らない。
- 処理速度は問題ない（約770段落で0.12秒。スタイル定義の全件検索が約3割だが、直す必要は薄い）。

## 進め方（この順に、段階ごとに別のPR）

### 0. PR #18 で入った回帰を直す（最初に行う・小）

PR #18 のマージ後に届いた再レビュー（5回目）で、PR #18 の修正が、修正前は正しかった書き方を崩していることが分かった（手元で、PR #18 前のmainでは正しく、後では崩れることを確認済み）。`tests/cases/misdetection_cases.json` の次の5例（source が「再レビュー5回目」）を、PR #18 前のmainと同じ結果に戻す。

| 例の名前 | 崩れ方 | 原因の箇所 |
|---|---|---|
| `R03_note_paren_article_title` | 日付入りの条タイトル「（令和6年4月1日以後に採用された者の特例）」が注記とみなされ、前の条の本文に結合される | `_RE_NOTE_PAREN`（日付・「ただし」） |
| `R01_para_unit_after_comma_item` | 読点で終わる号「（２）特殊健康診断、」の次の第2項「2 年に1回以上…」が号に結合される | `_para_num_is_continuation`（号の行が読点で終わる場合） |
| `R04_decimal_para_after_kanji_no_maru` | 句点の無い第1項「…休憩は1時間」の次の「2.1か月単位の…」が小数とみなされ結合される | `_starts_new_unit` の小数の判定 |
| `R02_heading_ref_after_comma_item` | 読点で終わる号の次の条「第11条（準用）　第1項の規定は…」が参照とみなされ結合される | `_starts_new_unit` の見出しの参照判定 |
| `R05_inline_item1_then_comma_item2` | 本文の途中に第1号がある行「従業員は、（１）…努め、」の次の「（２）のれんや…」が参照とみなされ結合される | `_starts_new_unit` の号の参照判定 |

- やること：上の5例を直す。ほかの例（特に「再レビュー1〜4回目」の例）の結果を変えないこと。
- 確認方法：`tests/cases/misdetection_cases.json` の全例を、変更前と変更後で解析して比べ、変わったのが上の5例だけであること（比べ方は、`current_outline` と今の出力を比べる小さなスクリプトで足りる）。`py/test_parser.py` の `_CASES` に5例を足す。
- 共通の原因：PR #18 で足した言葉の規則（読点・助詞・単位・日付）が、前後の文脈を十分に見ずに効いている。言葉の規則をさらに足しても同じことが繰り返されるので、直しきれないものは段階4・5（番号の並び・前後の単位で決める）に回してよい。その場合は、PR #18 前のmainの動きに戻すことを優先する。
- 推奨：Opus / medium

### 1. 目次の判定を先に行う（案1・小）

- やること
  - 目次の行（行末がリーダー記号「…・‥」やタブの後ろにページ番号、または「（第1条～第4条）」のような条の範囲で終わる章・条の行）を、停止語と本文の始まりの判定より前に見分け、前付けとして扱う。
  - 停止語（附則など）は、目次の行では止めない。
  - 本文の始まりの直前にある括弧だけの行（第1条のタイトル「（目的）」）は、前付けではなく本文に含める。
- やらないこと：手打ちでない目次（目次スタイルの段落）の扱いの変更。整形側（`apply_style.py`）の変更。
- 触るファイル・関数：`py/kisoku_parser.py` の `parse_kisoku`（段落ループの停止語・前付けの判定）、必要なら目次の行の判定関数を新しく作る。
- 従う既存パターン：`is_toc_paragraph`（目次スタイルの判定）、`_STOP_WORD_REF`（停止語の参照判定）。
- 確認方法：`tests/cases/misdetection_cases.json` の `P1_toc_with_fusoku`・`P2_toc_articles`・`N_manual_toc`・`F15_toc_without_toc_style_creates_empty_chapters`・`W_title_before_first_noch`・`F06_first_article_preceding_title_goes_to_front` が期待どおりになること。`py/test_parser.py` の `_CASES` に同じ形で足す。

### 2. テストの土台（段階0・動作は変えない）

- やること
  - `tests/cases/misdetection_cases.json`（PR #18 で集めた誤判定例。`current_outline` はPR #18時点の出力で、正解ではない）に、期待する構造（`expected_outline`）を付け、テストとして実行できるようにする。まだ直っていない例は「既知の失敗」として別に数え、CIを落とさない。
  - 書式ゆらぎテスト：正しく解析できるサンプル（`tests/samples/`）の解析結果を、PDF風に25〜40字で改行する、数字の前後に半角空白を入れる、条タイトルを別の行にする、項番号を「２．」形式にする、などの形に自動で書き換え、元と同じ構造になるかを比べる。`tests/make_messy_sample.py` の作り方を参考にする。
- やらないこと：解析・整形のコードの変更。
- 確認方法：新しいテストがCIで動き、既知の失敗の件数が表示されること。AGENTS.md の回帰テストの一覧と `.github/workflows/test.yml` に新しいテストを足す。

### 3. 見た目の判定結果を、段落ごとに一度だけ作る（案2・中・動作は変えない）

- やること：各段落を、行頭の記号の種類と番号、行末の種類（句点・読点・助詞・その他）、Wordの自動番号・スタイル・インデントをまとめた1つのデータに先に変換する。結合・分類・記号の学習・図の判定は、すべてそれを使い、結合した文字列を正規表現で切り直さない。使われていない旧処理（上の「回りくどい箇所」）を消す。
- やらないこと：判定の結果を変えること（変わったら、それは不具合）。
- 確認方法：回帰テスト（`tests/regression.py`）と段階0のテストが、すべて変更前と同じ結果になること。

### 4. 番号の並びで骨組みを決める（案3・中）

- やること
  - 条見出しの候補を全部集め、文書全体で番号が増えていく最も長い並びを採用する（枝番「第9条の2」・欠番・「第5条～第7条　削除」は許す）。並びから外れた候補（本文中の参照、目次、附則の条）は見出しにしない。章も同じ。
  - 番号が同じ候補が並ぶとき（第11条の中の「第12条に定める」と本物の第12条など）だけ、今の言葉の規則（`_REF_AFTER_HEADING`）で決める。
  - 条の中では、項番号が1ずつ増えるか、直前の行が文として終わっているかで、項・号・折り返しを決める。数量（「60 歳」「1.25倍」）や単位の語のリスト（`_QUANTITY_UNIT`）は、番号で決まらないときの補助に下げる。
  - 言葉の規則では見分けられず、PR #18 で直さなかった例（この段階か段階5で扱う）
    - 折り返し行頭の「第3章は適用しない」「第10条（定年）は適用しない」が偽の章・条になる（`P1_heading_ref_ha_to_yori_regression`）。「が・は」は「第2条（がん検診）　がん検診の…」と区別できないため、見出しの参照判定から外してある。番号の並び（第1条の中に第10条は来ない）で決める。
    - 読点の無い折り返し「…書類のうち／（１）の書類は…」が号に分かれる（`P2_marker_ref_without_comma_regression`）。
    - 読点で終わる柱書のあとの「（１）は…」が、参照（`M3_marker_ref_with_ha_ga_and_stop_word_with_space`：「…のうち、（１）は配偶者に限る」）か第1号（`P8_item1_after_comma_and_stop_word_ref`：「…にあたり、（１）のれんや看板を…」）かを区別できない。今は第1号として扱う（PR #18 前と同じ）。号の番号が続くか（（２）（３）が後ろに並ぶか）で決める。
- 未決の仕様（このときユーザーに聞く）
  - S1：①②で項を書く規則（条見出しの直後に柱書なしで①が来る）を項とみなすか。
  - S3：項番号が連番でないときの扱い（原本で番号が飛んでいると、その項が前の項に結合される）。
- 確認方法：段階0のテストの既知の失敗が減り、新しい失敗が出ないこと。既存5サンプルの結果が変わったら、差分をユーザーに見せ、了承を得てから `python3 tests/regression.py --update` で基準を更新する（AGENTS.md）。

### 5. 括弧行と号の階層を、前後を見て決める（案4・中）

- やること
  - 括弧だけの行は、次の単位が条見出しのときだけ条タイトルとし、それ以外は直前の項目の本文とする（保留と戻しの仕組みを減らす）。図の直後の括弧行も、次が条見出しなら条タイトルにする（⑤）。
  - 号の階層は、条（または項）ごとに入れ子で決める（④）。記号の無い行で入れ子の状態をリセットしない。
- 確認方法：段階4と同じ。

### 6. 残りの誤判定（上で直らなかったもの）

PR #18 の点検で見つかり、まだ直していないもの（`tests/cases/misdetection_cases.json` の名前）:
- 条見出しの書き方：「第2条【適用範囲】」「第3条：遵守義務」「第4条の2の2」「第5条～第7条　削除」「第二〇条」（`F05_article_delimiter_brackets_colon_subbranch`、`F11_kanji_numeral_hundred_ten_and_zero`）
- 条タイトル：「(適用範囲) ※…」「（遵守義務)」の全角・半角の混在、「（出向（在籍出向・転籍出向））」の入れ子、見出しの次の行の「（目的）」（`F12_merge_lines_paren_title_mismatch`、`F13_nested_parens_in_article_title`、`F09_title_on_line_after_article_heading`）
- 節（第1節）の判定（S4・節を整形結果にどう出すか仕様の判断が必要。`F10_chapter_absorbs_section_and_lead_text`）
- 号の記号：「（一）」「(１)」「十一　」（`C04a_kanji_paren`、`C04b_half_paren_full_digit`、`C13_kanji_11_space`）
- Wordの自動番号の号：既定の段落番号「1.」が項になる、箇条書き（・）が前の行に結合される（`R_list_number_style`、`S_list_bullet`）
- 号の細分の続き行が親の号に付く（`M_text_after_subitem`）
- 括弧のない条タイトル「第1条　目的」（S2・仕様の判断が必要。`T_article_title_noparen`）
- 軽微：漢数字「百十」の数値化（`O_kanji_110`）、「イロハ」順の番号の値（`C15_iroha`）
