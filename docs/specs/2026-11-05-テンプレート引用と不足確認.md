# テンプレート規程からの引用（⑤）と、足りない規程の確認（⑥）の改定案

2026-11-05 時点の案。別のセッションで、仕様を確認してから進める。

## 前提：今のアプリの作り（2026-11-05 時点）

- 解析：`py/kisoku_parser.py` が docx を章・条・項・号の木（JSON）にする。
- 編集：「⑤ 新旧対照表」の右側（改正案）で条・章を直接編集できる（`editor.js`、`index.html` の「改正案の編集」）。
  - 編集した木は端末の IndexedDB にファイルごとに下書きとして残る（外部には送らない）。
  - Worker へは `useTrees`（`worker.js`）で渡し、`py/web_entry.py` の `write_tree` / `_check_tree` で形を確かめてから使う。
- 新旧対照表：`py/comparison.py`（`view()` が画面用、`compare()` が Word 用）。
- 整形：`py/apply_style.py`。照合レポートは `py/verify_report.py`（編集による変更は別欄）。
- AI：Gemini API の Interactions API（Antigravity エージェント）で判定不能な段落をまとめて判定できる（`py/gemini_helper.py`）。本文全体を Google に送るため、有料枠のキーが前提。
- テスト：`AGENTS.md` の回帰テスト一式（CI でも実行）。

## ⑤ テンプレート規程からの引用

### 目的

ひな形（モデル就業規則など）の条文を、編集中の改正案に差し込めるようにする。

### 仕様案

1. **ひな形のデータ**
   - ひな形の条文を、今の木と同じ形（章・条・項・号）の JSON で持つ。
   - 出典・版（例：厚生労働省 モデル就業規則 令和○年○月版）と、取り込んだ日を必ず残す。
   - ひな形の docx を、今の解析（`parse_kisoku`）で木にする取り込みスクリプトを用意する。手作業で JSON を書かない。
2. **差し込み方**
   - 改正案の条の編集欄に「ひな形から条を挿入」を足す。
   - 章・条タイトル・本文の語で探し、選んだ条を「下に条を追加」と同じ位置へ入れる。
   - 入れた条は新旧対照表で「新設」になる（今の仕組みのまま）。
   - 既存の条を「ひな形の条で置き換える」も選べるようにするかは要相談（置き換えると「内容変更」になる）。
3. **差し込んだ条の扱い**
   - ひな形の「○○株式会社」「○日」などの空欄は、差し込み後に黄色く表示して、埋め忘れに気づけるようにする（任意）。
   - 新旧対照表の備考に「モデル就業規則（令和○年版）第○条に準拠」と自動で入れるかは要相談。

### 注意点

- **公開リポジトリに置けるのは、公開されているひな形だけ**。先生独自の規程や顧問先の規程はリポジトリに入れない（GitHub Pages で誰でも見られる）。独自のひな形を使いたい場合は、画面から docx を読み込んで、端末の中（IndexedDB）にだけ保存する形にする。
- ひな形は法改正で改訂されるので、版を持ち、古い版を使っていることが画面で分かるようにする。
- ひな形の条番号の参照（「第○条に定める」）は、差し込み先では番号がずれる。参照の書き換えは別の機能（未着手）。

### 推奨

Sonnet / medium（取り込みスクリプトと、編集欄に挿入の操作を足す機能追加。データの出典・版の扱いだけ先に決める）

## ⑥ 足りない規程の確認

### 目的

今の規程に、法令上必要な記載や、法改正で追加が必要な記載が足りているかを一覧で確認できるようにする。

### 仕様案

1. **チェック表のデータ**
   - 確認項目を JSON で持つ。項目ごとに、根拠（法令・条番号・施行日）、区分（絶対的必要記載事項／相対的必要記載事項／法改正対応／推奨）、探す語（複数・言い換え含む）、補足を持つ。
   - 最初の対象の例：
     - 労基法89条の絶対的必要記載事項（始業・終業の時刻、休憩、休日、休暇、交替制、賃金の決定・計算・支払・締切・支払時期・昇給、退職（解雇の事由を含む））
     - 相対的必要記載事項（退職手当、臨時の賃金・最低賃金、食費・作業用品の負担、安全衛生、職業訓練、災害補償・業務外の傷病扶助、表彰・制裁、その他全員に適用される定め）
     - 法改正対応（育児・介護休業法、ハラスメント防止、無期転換・労働条件明示 など）
   - **項目の中身（とくに法改正の施行日・内容）は、作業する時点で厚生労働省の一次資料で確かめてから入れる**。記憶やAIの回答で埋めない。
2. **判定**
   - まずはルールベース：探す語が条タイトル・本文に含まれるかで「あり（該当する条を表示）／見つからない／要確認」を出す。
   - AI による判定（Antigravity）は任意のオプションにする。本文全体が Google に送られる点は、今の AI オプションと同じ注意書きを出す。
3. **結果の表示**
   - 一覧（項目・区分・根拠・結果・該当する条へのリンク）。新旧対照表の条へジャンプできるようにする。
   - 「見つからない」項目から、⑤ のひな形の該当条を差し込めるようにする（⑤ のあとに作る場合）。
   - 結果を Markdown か Word で保存できるようにする（顧問先への説明用、任意）。

### 注意点

- 語の有無で判定するので、書いてあっても語が違えば「見つからない」、語があっても中身が古い（改正前の内容）ことは見抜けない。**最終判断は社労士が行う前提の補助ツール**であることを画面に明記する。
- 法改正のたびにチェック表を直す必要がある。チェック表に「確認した日」を持たせ、古くなったら画面に出す。
- 誤って「あり」と出すほうが危ない（見落としにつながる）ので、迷う判定は「要確認」に倒す。

### 推奨

Opus / high（法令の要件をデータにする判断と、誤判定の倒し方の設計が結果を左右するため。チェック表の中身は一次資料で確かめる）

## 進め方の案

1. ⑥ のチェック表の項目（区分・根拠・探す語）を先に作り、ユーザーが中身を確認する。
2. ⑥ のルールベースの判定と一覧を作る。
3. ⑤ のひな形の取り込みと差し込みを作る。
4. ⑥ の「見つからない」から ⑤ のひな形を差し込む連携を作る。

新しいセッションでは、このファイルを読んでから「どちらから始めるか」「ひな形の出典」「チェック表の対象範囲」をユーザーに確認すること。
