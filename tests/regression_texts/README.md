# 回帰テスト用の文章

整形の不具合やレビューの指摘を受けて作った、就業規則の文章の例を置く。
今後 `py/` や編集画面を直したときに、同じ失敗が戻っていないかを確かめるのに使う。

## ファイルの形
- 1ファイル1例。拡張子は `.txt`（UTF-8）
- `#` で始まる行は説明（目的・期待する結果）。それ以外の行が、docx の1段落ずつの本文
- 自動のテストで比べる期待値は、次の行で書く（`tests/test_regression_texts.py` が全ファイルを読む。CI でも実行）
  - `#> ` に続けて、期待する骨組みを1行ずつ（`show.py` の出力と同じ形）
  - `#hint> ` に続けて、付くはずの要確認の印（条見出しの疑い）を1つずつ。無いときは `#hint> （なし）`
  - `#>` の行が無いファイルは比べない（`heading_like_references.txt` は `tests/test_editor_split.js` が読む）

## 文章を足すとき
1. 本文と `#` の説明を書いたファイルを作る
2. 次のコマンドで骨組みを表示し、正しい形かを確かめる

```bash
python3 tests/regression_texts/show.py tests/regression_texts/<名前>.txt
```

3. 正しければ、その出力の各行の頭に `#> ` を付けてファイルの末尾に足し、`#hint>` の行も足す
   （直す前の不具合を記録するときは、出力ではなく「正しい形」を書く。直すまでテストは失敗する）
4. 下の一覧に1行足す

## 一覧
| ファイル | 確かめること |
|---|---|
| branch_hyphen.txt | 枝番をハイフンで書いた条見出し（第６条－２）が独立した条になる |
| loose_article_sharp.txt | 想定外の枝番（第６条＃２）の行が、独立した項として残り、要確認の印が付く |
| loose_article_inline.txt | 文の途中に結合された疑いの行（＃３）にも印が付く |
| loose_article_front.txt | 文書の最初の条が疑いの行のとき、前付けに印が付く |
| editor_split.txt | 画面の「ここから新しい条にする」で、印の付いた第3項から分けるとタイトルが取り出される |
| heading_like_references.txt | 見出しに似た本文中の参照。分割しても本文から文言を消さない（1行ずつ別の例） |
| range_kara_made.txt | 「第１６条から第１８条まで　削除」が、前の条に結合せず３つの削除条になる。本文中の「第５条から第７条までの規定」は見出しにしない |
| paren_num_mixed_width.txt | 半角(1)・全角（3）・⑷が混ざった号が、同じ階層の続き番号になる |
| para_dai_kou.txt | 「第２項　」と書いた項番号を第２項にする |
| article_colon_body.txt | 「第１条：本文」のコロンを本文に残さない |
| item_ref_after_particle.txt | 助詞で切れた号の折り返し先の「（２）の書類」を新しい号にしない |
| decimal_after_period.txt | 句点のあとの「１．２５×…」を号の「１．」にしない |
| quantity_after_particle.txt | 「少なくとも／２　週間前」の２を第２項にしない（番号が次の項番号と同じでも） |
| half_paren_item.txt | 「１）」形式の号を号にし、号の折り返しを結合する |
| lone_para_number.txt | 番号「２」だけの段落と次の段落を第２項にする |
